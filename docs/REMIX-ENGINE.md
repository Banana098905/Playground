# Remix Engine（Phase 4）

Create（Creation Engine）で作った作品を「改造・派生・合成」するための仕組みです。Creation Engine 本体（ブロックの仕様・インタープリター）は変えていません。Remix は同じブロックだけで動きます。

## 構成

| ファイル | 役割 |
|---|---|
| `js/remix/core.js` | 差分（`diff`）・概要文（`summarize`）・系統ツリー（`buildTree`）・名前の重複回避・`remix` フィールドの検証 |
| `js/remix/parts.js` | 部品の検証（`sanitize`）・切り出し（`extract`）・挿入（`insert`）・作品どうしの組み合わせ（`composeWorks`） |
| `js/remix/builtins.js` | 付属の部品 7 種（既存ブロックだけで構成。テストで実際に挿入して実行を確認） |
| `js/remix/store.js` | 保存層。変更履歴・下書き・部品ライブラリ・作品の操作（派生／上書き／復元） |
| `js/remix/io.js` | `.pzremix.json` の書き出し・検証つき読み込み、バックアップへの出し入れ |
| `js/pages/remix.js` | Remix Workspace の画面本体 |
| `js/pages/remix-panels.js` | 差分・系統ツリー・履歴・保存確認・並べて比較・読み込み確認 |
| `js/pages/remix-parts.js` | 部品ライブラリ・挿入・部品化・組み合わせ |

UI は計算を持たず、`PZ.remix.*` を呼ぶだけです。保存先は既存の `meta` ストア（`PZ.userdata`）なので、IndexedDB のバージョン変更・移行は不要です。

## Remix Workspace の使い方

1. **Remix** を開き「作品を開く」。自分の作品かサンプルを選びます。
   - **派生して開く**: 元の作品は変わりません。保存すると新しい作品（派生）になります。
   - **そのまま編集**: その作品を直接編集します。保存前の状態は履歴に残ります。
2. ブロックを追加・削除・複製（Ctrl+D）・並べ替え（ドラッグ／↑↓／Alt+↑↓）・つなぎ替え（ドラッグ）。数・色・条件・へんすう・つまみ・背景色も編集できます。クリック・ドラッグ・キーボードのどれでも操作できます。
3. プレビューは実行／一時停止／停止／リセット。変更はすぐ反映されます（切替可）。「変更前と並べて比べる」で、**同じ乱数の種で2つを同時に**動かします。
4. 下のパネル:
   - **変更**: 開いたとき（または最後に保存したとき）との差分。追加（緑）・削除（赤）・変更（橙）・接続変更（紫）。押すとそのブロックへ移動。
   - **部品**: 付属／自分の部品を挿入、選んだブロックを部品化、ほかの作品のスクリプトを組み合わせ、部品の書き出し・読み込み。
   - **履歴**: 保存した版の一覧。比較、**別の作品として復元**、ピン留め。
   - **系統**: 派生ツリー。開く／ここから派生。元が削除されても「削除済み」として残ります。
   - **へんすう / チェック**: へんすう・つまみの編集、ブロックの検証結果。
5. **保存**を押すと、変更内容の確認画面（名前・変更メモ・差分）が出て、確認後に保存されます。Ctrl+S、元に戻す Ctrl+Z、やり直す Ctrl+Y。

## 派生・系統

- 派生した作品は、元の**コピー**です（深いコピー）。元を後から変えても派生は変わらず、派生を変えても元は変わりません。
- 作品レコードの任意フィールド `remix`:
  ```jsonc
  "remix": {
    "v": 1,
    "origin": { "id": "元の作品ID|null", "sample": "サンプルID|''", "name": "元の名前", "ver": 3, "at": 0 },
    "lineage": [ { "id": "…", "name": "…" } ],   // 祖先（古い順）。元が削除されても系統を表示できる
    "summary": "直近の保存の変更概要",
    "parts": [ { "id": "…", "name": "…", "version": 1 } ]   // 使った部品
  }
}
  ```
  `parentId`（Phase 2 から）も引き続き記録します。`remix` が無い Phase 1〜3 の作品はそのまま読めます。
- 元の作品を削除しても、派生は壊れません（系統ツリーには「削除済み」の祖先として表示）。

## 変更履歴

- 保存のたびに 1 版を記録（名前・日時・種類・変更概要・メモ・内容）。種類: 派生元／保存／復元／読み込み／開始時の状態。
- **自動保存（下書き）と明示的な保存は別**です。下書きは `rxd:*`（最大 10 件・各 400KB）に控えるだけで、作品も履歴も変えません。
- 上限: 1 作品 30 版・合計約 1.2MB。超えると古い版から整理（最新・派生元・ピン留め（最大 5）は残す）。内容が前の版と同じなら増やしません。
- 履歴が無い作品を初めて上書きするときは、上書き前の状態を「開始時の状態」として残します。
- 別のタブで更新されていた場合は、上書きせずに「別の派生として保存／上書き／キャンセル」を選ばせます。
- 履歴の削除は作品の削除と連動させていません（削除の取り消しで戻せるよう、既定では残します。`R.work.forgetHistory` で消せます）。

## 再利用部品

- 部品＝ブロックの塊＋入力（作品側に必要なへんすう）＋出力（部品が値を入れるへんすう）＋設定値（挿入時に変えられる数・色・選択肢）＋バージョン。入出力は中身から自動判定します。
- 挿入時、部品が持つへんすうが作品と衝突したら**自動で別名**（`name_2`）にします。既存のへんすうに「つなぐ」ことも選べます（型が合わないと拒否）。足りない入力は、作る／つなぐ／自動作成から選びます。
- 挿入前に `insert()` を実行して結果をプレビュー（できない理由と直し方も表示）。挿入後に検証し、**新しく出たエラー**があれば挿入しません。元の作品は変更しません（Ctrl+Z でも戻せます）。
- 付属の部品: ランダムな色／マウスをなめらかに追いかける／一定時間ごとに数える／円どうしの衝突／壁ではね返って動く／複数の条件の組み合わせ／円をえがいてまわる。
- 作品どうしの組み合わせ（`composeWorks`）: 他作品のスクリプトを選んで取り込み。必要なへんすうの不足を検出し、名前の衝突を避け、未対応ブロックを含むものは理由つきで拒否します。

## 書き出し・読み込み（`.pzremix.json`）

```jsonc
{ "app": "playground-zero", "type": "remix-package", "format": 1, "appVersion": "4.0.0", "exportedAt": "…",
  "work": { "name", "description", "tags", "createdAt", "updatedAt", "creation": { … }, "remix": { … } },
  "history": { "versions": [ { "no", "at", "kind", "name", "summary", "note", "creation" } ] },
  "components": [ { …部品… } ],
  "dependencies": { "parts": [ { "id", "name", "version" } ] } }
```
- 読み込みは `inspect()`（検証のみ。何も保存しない）→ 確認画面 → `apply()`。構造・サイズ（8MB）・ブロック種類・参照・バージョンを検証し、不正なら**何も保存せず**理由を表示します。
- 作品は**必ず新しいID**で追加（名前に「(取り込み)」）。既存の作品は上書きしません。履歴・部品は取り込むか選べます。
- ファイルの中身は「許可リストのブロック名と値」としてしか読まず、**コードとして実行しません**。
- Phase 3 の `.pzcreate.json` もそのまま読めます。
- バックアップ（format 3 のまま）には、任意のルート項目 `remix: { v:1, components, histories }` を追加。Phase 3 のアプリで開いても作品は読めます（項目は無視）。

## 制限（未実装・割り切り）

- ブロックの「つなぎ替え」は、Create と同じ操作（ドラッグで別の場所・別のブロックの中へ移動、値ブロックは入力欄の「◇」で差し替え）の範囲です。接続の線を引く専用の画面はありません。
- 差分は「ブロックID」を基準にした比較です。ID が重ならない版どうし（別々に作った作品）では、文面ベースの簡易比較になります。
- 3 者マージ（同じ元から分かれた 2 つの派生を自動で統合）は未実装です。組み合わせは「スクリプトの取り込み」です。
- 履歴は上限つきです（30 版・約 1.2MB/作品）。画像（サムネイル）は履歴に含めません。
- クラウド同期・共同編集・公開ギャラリーはありません（サーバー不要の範囲）。
